- Detail installs, single updates, update all and background updates now share task state, preventing duplicate downloads and installs. External hand-offs remain pending confirmation; a batch with hand-offs reports that its requests have been processed.
- The store remembers the release that supplied the installed APK, fixing repeated update prompts for variants such as APK 4559 from release 4571. Later releases, republished releases and replacements installed outside the store still trigger the appropriate update checks.
- Explicit APK preferences and successful installation records are stored separately. Installing the default no longer pins a preference; failures keep manual choices, and restoring automatic selection keeps installation history. All entry points share recommendations and probe caches, with the recommended APK first in the asset list.
- Automatic version selection follows refreshed releases while manually selected history stays selected. Removed resources are shown as unavailable, and older releases never stand in for the latest. The install button describes the selected APK as an install, update, reinstall or downgrade.
- Selected APKs go directly to the installer without extra compatibility blocks, warnings or confirmations. Renamed packages are tracked correctly, failed or cancelled installs download afresh on retry, and the installed list refreshes more reliably on devices with many apps.
