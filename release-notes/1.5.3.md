修复：

- 文件名里的 `minsdk` 标记不再决定能否安装：以前作者把文件名写错（或版本号只是习惯）就会让模块在详情页禁用安装、并从更新列表消失；现在只显示一行提示，真正的判断交给安装包自己的声明。
- 原生库 ABI 不匹配不再直接拒绝安装：安装本身不会因此失败，模块也可能根本不用 native 部分，所以改为提示，装不上时仍会按一次失败处理。
- 文件名像「配套应用」（client/provider/bridge/demo 等）的 APK，在读过安装包、确认它就是本模块后可以正常安装，不再永久灰掉。
- 连续三次安装失败不再让模块永久退出更新列表：失败只是提示和重新挑选变体，模块仍会出现在更新里，可以在详情页重试。
- 更新检查遇到不知道发布时间的旧「不适用」结论时改为重新判断，而不是继续隐藏。

Fixed:

- A `minsdk` marker in the file name no longer decides whether a build can be installed: a mislabelled name used to disable the install button and hide the module from updates - it is now a hint, and the APK's own manifest decides.
- A native-library ABI mismatch no longer refuses the install outright: installing never fails on it and the module may not use its native part at all, so it is a warning (a real failure still counts as one attempt).
- An APK whose name looks like a companion app (client/provider/bridge/demo, ...) becomes installable once its archive shows it is the module itself.
- Three failed installs no longer remove a module from the update list for good: failures only trigger re-probing, the module stays listed and can be retried from its page.
- A stored "not applicable" verdict with no publish time is re-checked instead of hiding the module again.
