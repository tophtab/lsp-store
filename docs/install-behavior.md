# 安装与更新的当前规则

用户选择 APK 后，LSP Store 下载文件并直接交给 root 或外部安装器。应用不按包名、
模块声明、minSdk、ABI、框架 API 或 debug 属性拒绝安装，也不添加警告或二次确认。
系统安装器自己的权限请求和安装结果由它处理。

文件名和远程探测只用于给自动更新选择默认 APK；资源列表中的每个 APK 都可手选。
明确选择会保存去掉 release 版本号的文件身份和原有 ABI/API 等维度。
TRUSTED 不影响手动探测，探测失败也不会覆盖明确选择。

下载后读取 manifest 的包名和版本仅用于安装结果记账。读取失败仍会安装，使用请求中的
信息作为回退。新包确认安装成功后才保存仓库链接和实际包名。旧包与新包同时存在时，
优先跟踪用户已确认的包；旧数据没有这个记录时，跟踪该仓库关联的最新已装副本。

安装器报告失败或用户放弃未完成的安装后，该下载缓存失效，下一次尝试重新下载。
没有 APK、暂时无法访问仓库或历史 NOT_APPLICABLE 判定不会把更新静默隐藏。
更新时优先使用用户点击的目标 release；其 APK 不再可用时，可使用同一渠道中 versionCode
更高的 APK。详情出现更高版本不会再被误报为旧版本，旧镜像也不会替换成更低版本。
每次详情请求重新按端点和用户的镜像偏好选择主机，一次回退不会固定后续请求。

进程存活时动态监听包变更；进程重启和返回前台时补偿扫描安装结果。
交互安装在用户回到应用后才启动下一项，后台自动更新使用静默 root 路径。
root 命令请求替换与降级（`pm install -r -d`）；最终安装是否成功由设备决定。

`variant-selection.md` 与 `variant-implementation-reference.md` 保留历史调研和设计；
其中关于拦截、警告、确认和“不适用”的旧规则不再是当前产品行为。
