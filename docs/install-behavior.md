# 安装与更新的当前规则

用户选择 APK 后，LSP Store 下载文件并直接交给 root 或外部安装器。应用不按包名、
模块声明、minSdk、ABI、框架 API 或 debug 属性拒绝安装，也不添加警告或二次确认。
系统安装器自己的权限请求和安装结果由它处理。

文件名和远程探测只用于给自动更新选择默认 APK；资源列表中的每个 APK 都可手选。
明确选择会保存去掉 release 版本号的文件身份和原有 ABI/API 等维度。
TRUSTED 不影响手动探测，探测失败也不会覆盖明确选择。

下载后读取 manifest 的包名和版本仅用于安装结果记账。读取失败仍会安装，使用请求中的
信息作为回退。新包确认安装成功后才保存仓库链接和实际包名。旧包与新包同时存在时，
优先跟踪用户已确认的包；旧数据没有这个记录时，跟踪该仓库关联的最新已装副本。

安装器报告失败或用户放弃未完成的安装后，该下载缓存失效，下一次尝试重新下载。
没有 APK、暂时无法访问仓库或历史 NOT_APPLICABLE 判定不会把更新静默隐藏。
更新时优先使用用户点击的目标 release；其 APK 不再可用时，可使用同一渠道中 versionCode
更高的 APK。详情出现更高版本不会再被误报为旧版本，旧镜像也不会替换成更低版本。
每次详情请求重新按端点和用户的镜像偏好选择主机，一次回退不会固定后续请求。

进程存活时动态监听包变更；进程重启和返回前台时补偿扫描安装结果。
交互安装在用户回到应用后才启动下一项，后台自动更新使用静默 root 路径。
root 命令请求替换与降级（`pm install -r -d`）；最终安装是否成功由设备决定。

`variant-selection.md` 与 `variant-implementation-reference.md` 保留历史调研和设计；
其中关于拦截、警告、确认和“不适用”的旧规则不再是当前产品行为。

## 任务、来源与明确偏好

详情安装、已安装页单项更新、全部更新和后台自动更新共用应用级 `InstallTaskRegistry`。
解析 release 前认领仓库任务，随后关联已装包名和 APK 实际包名。任务覆盖排队、准备、下载、
等待安装、安装中及外部安装待确认；重复请求展示已有任务，不再次下载，也不算本批的新任务。
每次任务有独立 ID，清理、取消和进度回调只能操作这个 ID。启动时先恢复持久化 pending，
再接受请求；返回前台只结算恢复前台之前已待确认的任务，旧回调不会释放随后开始的新任务。

`ResolvedInstallTarget` 固定本次选择的 release tag、版本、发布时间、APK 身份、变体和是否
明确选择。准备结果与 pending 均保存实际选择的来源，使用更高版本替补时记录替补的来源。
安装前读取实际 APK 身份并写 pending；root 返回和外部安装器返回共用确认入口。确认必须
看到新的 PackageManager 更新时间，并核对可读取的 APK 包名、版本码和版本名。记录先写入，
pending 后清理。无法读出 APK 身份时仍允许安装，但不会据此补造已完成 release。
旧 pending 可按旧规则结算，不补造来源记录。

明确偏好和 `ConfirmedInstallRecord` 独立保存。资源列表手选并提交安装才写偏好；默认按钮
不写偏好。已安装页仍可单独保存偏好。失败保留偏好，成功记录不覆盖偏好；恢复自动选择
只清除明确偏好。推荐顺序为明确偏好、有效成功来源或可靠的已装变体证据、设备匹配、稳定
兜底。所有入口先读取共享探测缓存，相同资产并发探测合并；资源列表把真正推荐的 APK 放首位。
详情只接受当前 release 的当前探测请求，刷新后的旧结果不能覆盖当前选择。

成功来源记录包含 PackageManager 包名、版本码、版本名及 `lastUpdateTime`。这些信息任一
不匹配，记录立即失效；匹配时按来源 release 比较后续更新，同一 tag 未重新发布不重复提示。
例如 release `4571` 的 APK 实际为 `4559`，确认安装后不反复提示该 release，后续更高
release 和重新发布仍可检测。来源信息不足时沿用原版本与发布时间比较规则。

详情自动选择随刷新跟随最新目标，手选历史 tag 保持不变；手选资源被移除时显示不可用。
缺少最新目标时只允许同渠道更高版本替补，不用低版本冒充最新；历史 APK 仍可手选。
按钮优先依据所选 APK 的实际版本显示安装、更新、重新安装或降级安装，缺少 APK 版本时
结合所选 release 和有效成功记录；信息不足时使用安装或重装。按钮与资源行共用同一个目标。

批量下载保持并发上限，安装按下载完成顺序串行，Store 自身最后安装。外部交接不等待全部
结果才结束批量：失败、跳过、取消仍优先显示；存在外部交接时显示“批量更新请求已处理”，
全部确认成功才显示“全部模块更新完成”。后台自动更新仍只使用静默 root。

旧资产记忆一次迁移为明确偏好，纯 PackageManager 种子保留为本机安装证据。备份只携带
用户偏好，成功来源记录不作为可移植确认导入；合并保留本地确认，替换清除旧确认。
新字段均可选，迁移标记防止清除偏好后从旧字段再次恢复。
