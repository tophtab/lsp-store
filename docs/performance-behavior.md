# 性能、扫描与缓存的当前规则

本文说明基于 1.6.0 实施的运行成本优化。安装、明确 APK 偏好、来源确认和改包名跟踪的
规则见 [install-behavior.md](install-behavior.md)，发布步骤见 [release-process.md](release-process.md)。

## 资料库与列表计算

资料库字段先从 DataStore 提取原始值，通过 `distinctUntilChanged` 后再解码。
收藏与最近浏览的写入只通知各自的订阅，关键词忽略字段也采用同样的去重规则。
备份和恢复继续读取、写入原有字段和格式。

首页索引变化时建立包名索引；索引、忽略集合或忽略关键词变化时计算两组完整货架。
搜索从已按发布时间排序的列表筛选，保持标题、包名、简介的大小写无关匹配。
安装徽标在安装列表或关联变化时计算；收藏和最近浏览列表复用包名索引。

## 安装查询

`getInstalledModule(packageName)` 实时查询一个包，绕过完整列表的 30 秒 TTL。
详情只查询仓库包名与已关联的改名包，继续优先选择已确认的副本；旧数据按版本码、
更新时间和包名选择最新副本。pending 恢复只查询相关目标包，一个包读取失败时保留
该 pending，其他包仍可结算。取消向调用方传播。

完整列表扫描仍通过 `getInstalledPackages(0)` 枚举应用。metadata、provider、标签、ABI
与 APK 标记的读取按包复用，以版本码、版本名、更新时间、基础和拆分 APK 路径、系统
SDK、应用 SDK/flags、ABI 路径和语言作为失效条件。未成功读取的包保持可重试；APK
不可读与有效非模块 APK 分开处理。卸载时清除该包的扫描信息。语言变化也会绕过列表 TTL。

## 下载与通知

下载任务内部始终记录最新字节数，纯进度最多每 100 ms 发布一次。开始、暂停、恢复、
取消、失败和完成立即发布，完成时以文件实际长度结算。每次尝试有独立身份，旧回调
不能更新已清理、已取消或已被重试替代的任务。等待下载的订阅只观察该任务。

前台下载通知的纯进度更新最多每秒一次；任务成员或阶段变化立即更新，最后一个活动
任务结束时服务立即停止。这个节流不改变安装任务的阶段或下载并发上限。

## Range 探测

HTTP 206 校验 `Content-Range`、声明长度与实际长度，最多读取请求长度加一个用于
发现超长响应的字节。单次读取上限为 8 MiB。HTTP 200 只用于长度明确且等于请求
长度的完整文件；异常响应和超时继续回退到现有 APK 选择逻辑。

同一资产的互斥锁计入等待者，在最后一个使用者退出时移除，包括取消和异常。
成功探测沿用 500 项持久化 LRU；失败缓存保留 10 分钟，并在读取和新增时清理过期
项、限制到 500 项。父任务取消不会记为探测失败，也不会进入失败缓存。

## 索引与文件缓存

索引继续同步全部分页，并沿用 6 小时 TTL、后台检查频率、镜像顺序和 6 页并发上限。
会话第一次刷新获取当前来源的完整索引。官方分页与备份单文件的回退顺序遵循镜像
选择；切换来源会重新执行会话刷新。

同一来源的重叠刷新共享在等待期间完成的成功结果。随后独立发起的强制刷新仍完整
同步。失败、取消和普通离线读取的旧缓存回退不会被计为成功的网络刷新。

索引、安装列表和探测 JSON 先写同目录临时文件并同步，再原子替换目标文件，格式
兼容旧缓存。写入失败仍保留旧文件，网络结果可以继续用于内存展示。
`clearCache()` 在缓存互斥锁内清理状态和文件、推进写入代次；清理前启动的请求可以
返回结果给原调用方，但不能把缓存写回。后续新请求可正常保存新缓存。

## 图标与 README

应用图标使用 Coil，PackageManager 读取及 bitmap 转换在后台执行，内存缓存按包名、
更新时间和像素尺寸区分。占位和读取失败时继续显示原有字母图块。

README 在后台解析，页面保留不含 URI handler 的结果，返回时可立即恢复列表项数量。
顶层内容逐块进入详情页的同一个 LazyColumn；表格、图片、链接和嵌套折叠保持原有
渲染。折叠状态使用 `rememberSaveable`；同一文档改变主题时保持当前列表项数量。

## 验证与真机对比

本地检查使用完整 lint 与单元测试：

```bash
./gradlew :app:lintDebug :app:testDebugUnitTest --stacktrace
```

`PreferenceFlowsTest`、`HomeShelvesTest`、`InstalledPackageCacheTest`、
`PendingInstallQueriesTest`、`DownloadProgressTest`、`HttpRangeSourceTest`、
`ProbeRegistriesTest`、`RangeProbeTest`、`IndexRefreshTest`、`AtomicCacheFileTest` 和
`ReadmeDocumentTest` 覆盖字段通知、排序、单包查询、失效条件、节流、异常响应、取消、
缓存上限、原子替换与清理竞态。HTTP 测试使用本地服务，联网仓库抽样测试保持可选。

真机收益需另行记录。本次环境的 `adb devices` 列表为空，尚未测量启动时间、掉帧或耗电。
对比时使用同一设备、相同应用集合、相同 release/APK 与网络条件，分别记录基线提交和
优化提交、系统版本、语言及下载并发数。每个场景重复至少五次，报告中位数和范围。

| 场景 | 操作 | 记录指标 |
| --- | --- | --- |
| 详情打开 | 依次打开直接安装、改名副本与双副本模块，返回再打开 | `getInstalledPackages` / `getPackageInfo` 调用次数、首屏时间、主线程耗时 |
| 列表与搜索 | 滚动已安装列表，连续输入搜索词，切换收藏与最近浏览 | 图标读取和 bitmap 转换线程、主线程长任务、帧耗时与掉帧 |
| 长 README | 打开包含图片、表格和 details 的长文档，滚动、展开、离开后返回，再切换主题/翻译 | 解析线程与次数、活跃 Compose 块数、滚动和折叠恢复、帧耗时 |
| 并发下载 | 以相同并发数下载同一组 APK，暂停、恢复、取消其中一项 | UI 进度发布次数、通知更新次数、最终字节数与任务身份 |
| 安装结算 | 安装、同码替换、卸载、改包名双副本和返回前台 | PackageManager 查询次数、pending 与确认来源状态 |

使用 Android Studio System Trace 比较主线程耗时与帧时间；需要准确调用次数时单独用
方法跟踪记录，避免把方法跟踪自身的开销算进帧率收益。可同时保留系统帧统计：

```bash
adb shell dumpsys gfxinfo io.github.tophtab.lspstore reset
# 执行同一组滚动与详情操作
adb shell dumpsys gfxinfo io.github.tophtab.lspstore framestats > framestats.txt
```

截图与交互应核对表格图片、链接打开、折叠恢复、安装徽标、搜索顺序及最终下载大小。
实测记录完成后再据此评价收益；单元测试中的调用计数和虚拟时钟结果用于验证路径与频率。
